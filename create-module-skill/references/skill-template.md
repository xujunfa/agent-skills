## 填充要点

### description 撰写规则

1. **以触发条件为核心**，不要描述 skill 做什么
2. **至少 5 个真实触发短语**，中英文混合
3. 收集方法：回忆你过去 10 次涉及这个模块时，最常用的口语化表达
4. 例如 revision 模块："revision 没显示"、"accept 不工作"、"审阅模式"、"track changes"

### 关键文件速查表规则

1. **只放入口文件**，不超过 10 行
2. 选择标准：如果一个开发者第一次接触这个模块，他最先需要打开哪些文件？
3. 不要把所有文件都列出来 — 那是 architecture.md 的职责

### 按需加载指引规则

1. 必须与 references/ 目录下的文件**一一对应**
2. 如果有自定义 references 文件，需在表格中增加对应行
3. 场景描述用用户视角的自然语言，不要用技术术语

### 注意事项规则

1. 只放**跨场景通用陷阱**，不论做需求还是修 bug 都需要知道的
2. 每条一行，不展开解释（详细排查路径放在 common-bugs.md）
3. 常见类型：平台差异（Mobile vs PC）、ID 格式陷阱、隐含的状态依赖
