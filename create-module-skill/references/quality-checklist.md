# Module Skill 质量检查清单

完成所有文件后，逐项检查。未通过的项必须修复后才能交付。

---

## SKILL.md 索引质量

- [ ] description 包含 5+ 个真实触发短语（中英文混合）
- [ ] description **不包含**流程描述，只有触发条件
- [ ] Claude 使用指令段完整（先看表格 → 按需读取 → 逐个加载）
- [ ] 模块定位不超过 2 行
- [ ] 关键文件速查表 ≤ 10 行，只放入口文件（不是所有文件）
- [ ] 按需加载指引与 references/ 文件一一对应
- [ ] 注意事项 ≤ 5 条，每条是跨场景通用陷阱
- [ ] 整个 SKILL.md 不超过 80 行

## architecture.md

- [ ] 有组件关系图（文字或 ASCII）
- [ ] 有至少 2 条核心调用链（含最常见操作和最易出错操作）
- [ ] 有关键设计决策及其"为什么"（不只是"是什么"）
- [ ] 如果依赖的模块有 module-* skill，有交叉引用
- [ ] 不超过 200 行

## data-model.md

- [ ] 核心类型只保留关键字段，不是全量复制源码
- [ ] 有 ID 格式对照表（格式 → 来源 → 检测方法）
- [ ] 有存储结构说明（数据在哪里、怎么关联）
- [ ] 不超过 200 行

## common-bugs.md

- [ ] 每个 bug 分类有明确的「症状 → 排查路径」（线性格式或决策树格式）
- [ ] 线性排查路径按可能性从高到低排序；决策树按条件分支清晰 narrow down
- [ ] 包含「已知陷阱」— 让 Claude 跳过试错直接命中的经验
- [ ] 有 Edge Cases 表（来自 TODO/FIXME）
- [ ] 不超过 200 行

## dev-patterns.md

- [ ] 有扩展点总览表
- [ ] 每个模式有「需要修改的文件」清单（按顺序）
- [ ] 有至少一个现有功能作为参考实现
- [ ] 有「隐含步骤」checklist（容易遗漏的）
- [ ] 不超过 200 行

## debug-tooling.md（如适用）

- [ ] 有 Logger namespace 列表
- [ ] 有 Feature Flag 对照表
- [ ] 有可直接在控制台执行的调试命令（不是伪代码）
- [ ] 有断点建议（场景 → 断点位置 → 观察什么）
- [ ] 不超过 200 行

## 自定义 references 文件（如有）

- [ ] SKILL.md 的「按需加载指引」已同步更新
- [ ] 文件内容聚焦于该文件的主题，不与默认文件重复
- [ ] 不超过 200 行

## 整体知识质量

- [ ] 知识通过 "30 秒判断" 测试 — 每条知识能让 Claude 在 30 秒内做出正确判断
- [ ] 不是代码搬运 — 组织成决策路径而非罗列代码位置
- [ ] 向用户收集过补充反馈 — 用户经验是最关键输入
- [ ] 场景验证通过：bugfix（3 步内定位）+ feature（完整文件清单）+ 触发准确性（5+3）
- [ ] 已检查无与已有 module-* skill 的内容冲突
